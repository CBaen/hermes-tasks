# Hermes Tasks Collaboration And Autonomy Capabilities

## Root Label

- Purpose: Reusable capabilities for how Guiding Light and Uma collaborate without unnecessary pauses while preserving final approval for risky actions.
- Belongs here: Standing permission tiers, decision queues, interruption rules, parallel-work protocols, approval gates, user/agent handoff patterns, and cognitive-load-reduction workflows.
- Does not belong here: Raw private conversations, secrets, account credentials, runtime logs, or source-of-truth project docs that belong in the owning project root.
- Related roots:
  - `capabilities/` - baseline project operating capabilities
  - `capabilities-connections-control/` - connection/control capabilities that need approval boundaries
  - `capabilities-agent-infrastructure/` - infrastructure supporting parallel work
  - `/home/guidingl/Uma/OPERATING-FOUNDATION.md` - cross-project collaboration foundation

## How To Use This Root

1. Start here when a task asks what Uma may do independently versus what needs user approval.
2. Encode reusable collaboration patterns as capabilities, not as scattered chat promises.
3. Keep the user in charge of business meaning, risk, money, legal/account decisions, public/client-visible actions, and final submissions.
4. Let Uma own safe technical execution, verification, packaging, and option preparation.
5. Use decision queues to batch non-urgent choices instead of interrupting every time.

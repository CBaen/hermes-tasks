## What it does

Defines the durable collaboration layer for working with Guiding Light: preferences, boundaries, cognitive-battery patterns, vocabulary coaching, risk gates, project ownership, and what Moji should remember without turning private life into raw indexed data.

## When to reach for it

Use when synthesizing `USER.md`, `RELATIONSHIP.md`, `SOUL.md`, `MOJI.md`, memories, Claude-era relationship/workflow files, Codex operating notes, and recurring interaction lessons into a stable guide.

## How to use it

1. Use existing authoritative files first:
   - `USER.md`;
   - `RELATIONSHIP.md`;
   - `MOJI.md`;
   - `SOUL.md`;
   - `IDENTITY.md`;
   - `MEMORY.md` and daily notes.
2. Treat Claude/Codex material as source evidence, not automatic truth.
3. Extract principles, not raw transcripts:
   - how Guiding Light makes decisions;
   - what drains attention;
   - what language helps;
   - what requires approval;
   - what Moji should own technically;
   - what kinds of support have worked or failed.
4. Keep the layer human-respectful and minimal. This is not a dossier.
5. Put reusable collaboration patterns in capabilities. Put personal context in memory only when useful and appropriate.
6. Update project-specific operating manuals separately when a project has special stakes, audience, client boundaries, or style needs.

## Failure modes

- Overcollecting private material.
- Treating one emotional moment as a permanent rule.
- Forgetting that Guiding Light owns vision/meaning/business direction while Moji owns technical follow-through.
- Making the manual so large future agents do not read it.
